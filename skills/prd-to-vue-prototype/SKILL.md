# PRD 到 Vue 原型工程

## 适用场景

当用户希望“根据 PRD 快速做出可运行原型工程”时，使用本技能。
当输入 PRD 由 `SenseCare-product-master` 生成时，必须优先按其固定结构解析并映射实现。

默认约束：
- 仅前端原型，不接真实后端
- 必须使用假数据/Mock 适配交互
- 核心业务实体必须可演示 CRUD（增删改查）
- PRD 需求必须逐条映射到实现项

默认技术栈：
- Vue 3
- JavaScript（非 TypeScript）
- Vite
- Pinia
- Ant Design Vue

## PRD 输入兼容规则（SenseCare-product-master）

若检测到 PRD 具有如下特征，则按“SenseCare PRD 模式”处理：
- 一级章节为：`1. 项目背景`、`2. 业务流程简述`、`3. 需求总览`（含 `R1/R2…` 编号表格）、`4. 详细功能需求说明`
- 需求主体在 `4.x` 模块下展开，每个模块**标题下先有一条“用户故事”**（句式：`作为[角色]，我希望[能力]，以便[价值]`）
- 子结构固定为：
  - `4.x.1 功能说明`（开头先写 **位置** 与 **目标**）
  - `4.x.2 业务流程说明`（**正文内嵌 Mermaid 代码块**，无文档末尾图表附录）
  - `4.x.3 界面说明`
  - `4.x.4 交互说明`
  - `4.x.5 异常处理与边界说明`
  - `4.x.6 产品上下文说明`（可选，仅当命中 `reference-context/` 时存在）

解析与映射要求：

1. **复用 PRD 自带需求编号**：`3. 需求总览` 表格里的 `R1/R2…` 编号、名称、类型、优先级，必须直接作为原型“需求映射表”的主键，**不要自行另编 `R01/R02`**。
2. **用户故事 → 演示主线**：每个模块标题下的“用户故事”用于：
   - 推导原型的演示路径（角色登录态、首屏入口）
   - 推导核心 demo 操作脚本（用户故事中的“能力/动作”就是必须可走通的交互）
3. **`4.x.1 功能说明` 拆解**：
   - **位置** → 直接对应 `vue-router` 路由路径与导航层级（嵌套菜单/侧边栏定位由位置决定）
   - **目标** → 写入原型 README 的“演示主线”说明
   - **输入输出 / 关键规则 / 成功标准** → 表单字段 schema、Mock 初始数据、单元演示判定
4. **`4.x.2 业务流程说明` 中的 Mermaid → Pinia 状态机**：
   - `stateDiagram-v2` 中的每个**中文命名状态**，必须在 store 的 `state` 中有对应稳定 key（如“分析中态” → `analyzing`），中文原名用注释保留
   - `sequenceDiagram` 中跨角色交互的每条消息，对应 1 个 store action
   - `flowchart` 中的判断分支必须在原型上以可点击路径全部覆盖
5. **`4.x.3 界面说明` → 渲染层（落实 A、D 规范）**：列表列、表单项、文案、空态、截断规则、分页/无限滚动方式。**PRD 给出的具体文案（双引号包裹的静态文案）必须 1:1 落地**，不允许擅自改写。
6. **`4.x.4 交互说明` → 交互层（落实 B、C、F 规范）**：
   - “生命周期六步法”直接对应按钮的：`disabled` 条件 / 默认态 / 点击事件 / `loading` 态 + 防抖时长 / 异常分支 / 成功后跳转或刷新
   - PRD 中明确写出的数字常量（防抖 800/1000/1200ms、超时 10s/12s、字数上限、缓存清理时长等）必须 **1:1 落地**到 `src/constants/` 下的常量模块，不得改成“默认值”
   - 表单校验时机（实时 / 失焦 / 提交时）按 PRD 写明的方式实现
7. **`4.x.5 异常处理与边界说明` → 兜底层（落实 E 规范）**：弱网降级、并发抢占、合规拦截、系统级中断的弹窗优先级与遮罩策略。
8. **`4.x.6 产品上下文说明`（如有）→ 模块隔离边界**：
   - “模块归属”（Common 公共能力 / 助理型 / 工具型 / 问答型 / Qt 客户端底座）决定原型该页面挂在哪个壳子下
   - “明确不影响”列表是**反向白名单**：原型不要顺手实现这里列出的其他模块
   - 不在代码中硬编码产品叙述文案，只用其约束信息架构和导航
9. **顶层文档不存在“流程与状态图表”“附录”“图片管理”章节**，不要按这些章节去找内容。

## 执行流程

按以下顺序执行，不跳步。

### 第 1 步：读取并结构化 PRD

1. 提取 PRD 的核心对象：
   - 目标用户（来自模块标题下的“用户故事”角色）
   - 关键业务流程（来自 `2. 业务流程简述` 与各模块的 `4.x.2` Mermaid）
   - 页面/模块（来自 `4.x.1` 的“位置”）
   - 功能点（来自 `4.x.1` 的核心能力与输入输出）
   - 约束与非功能需求（来自 `4.x.4` 与 `4.x.5` 中的具体数值与边界）
2. 生成“需求映射表”：
   - **SenseCare PRD 模式**：直接复用 `3. 需求总览` 表格里的 `R1/R2…` 编号，不重新编号
   - **非 SenseCare 标准 PRD**：自行使用 `R01/R02` 编号
3. 如果 PRD 有明显缺口（字段不明确、流程断点、验收标准缺失），先提最小必要澄清问题，再继续实现。
4. 若是 SenseCare PRD 模式，按以下顺序拆分原型任务，并与 `Rxx` 建立双向映射：
   - 模块标题下的“用户故事” → 演示主线
   - `4.x.1` 位置/目标 → 路由与页面壳
   - `4.x.2` Mermaid → store 状态机与 actions
   - `4.x.3` → 视图组件与文案
   - `4.x.4` → 按钮状态机、表单校验、防抖/超时常量
   - `4.x.5` → 异常分支与降级提示
   - `4.x.6`（如有）→ 模块归属与隔离边界

需求映射表格式（SenseCare 模式推荐）：

```markdown
| 需求ID | PRD定位 | 用户故事(角色/价值) | 原型实现模块 | 页面/路由 | Store/Action | 状态 |
|---|---|---|---|---|---|---|
| R1 | 4.1 | 临床医生/降低录入负担 | MedicalRecordPage | /copilot/medical-record | useMedicalRecordStore | 待实现 |
```

### 第 2 步：先给实施蓝图，再落代码

先输出以下内容供确认（如用户未要求跳过）：
1. 信息架构（页面树 + 路由）
2. 组件与状态拆分（Pinia Store 列表）
3. Mock 数据边界（哪些数据静态、哪些可交互修改、哪些字段可 CRUD）
4. 里程碑（最小可运行版本 -> 可演示版本）

蓝图格式：

```markdown
## 原型蓝图
- 路由：...
- 页面：...
- 核心组件：...
- Pinia Store：...
- Mock 数据：...
```

### 第 3 步：创建工程

优先使用稳定脚手架命令创建项目，然后安装依赖并验证可启动。

推荐命令（按需执行）：

```bash
npm create vite@latest <project-name> -- --template vue
cd <project-name>
npm install
npm install pinia vue-router ant-design-vue @ant-design/icons-vue
```

然后完成基础接入：
- 在入口注册 `Pinia`
- 配置 `Vue Router`
- 配置 Ant Design Vue 全局或按需引入
- 创建基础布局壳（导航、内容区、页脚可选）

### 第 4 步：按“需求映射表”逐条实现

实现时必须同步更新映射表状态：
- `待实现` -> `已实现`
- 若暂缓，标记 `降级实现` 或 `待确认`

每实现一条需求，最少落地：
1. 对应页面或组件
2. 相关状态管理（若需要）
3. 交互逻辑（使用 Mock）
4. 基础可见性验证方式（手动路径或操作步骤）

其中涉及核心业务实体时，必须覆盖：
1. Create：新增记录（表单或弹窗）
2. Read：列表/详情查看
3. Update：编辑并保存
4. Delete：删除并有二次确认

### 第 5 步：输出可验收结果

完成后必须提供：
1. 项目目录结构（简版）
2. 运行命令
3. 已实现需求清单（引用 `Rxx`）
4. 未实现/降级项清单（含原因）
5. 下一步建议（如接 API、补鉴权、补测试）
6. 若输入为 SenseCare 标准 PRD，增加“PRD 章节覆盖率”说明（至少列出已覆盖的 `4.x` 与未覆盖原因）

输出模板：

```markdown
## 原型交付结果

### 1) 运行方式
- 安装：`npm install`
- 启动：`npm run dev`

### 2) 需求映射结果
| 需求ID | PRD定位 | 实现说明 | 代码位置 | 状态 |
|---|---|---|---|---|
| R1 | 4.1.2 | ... | ... | 已实现 |

### 3) 未完成项
- R3：原因...

### 4) 演示路径
- 首页 -> 列表页 -> 详情页 -> 提交流程

### 5) PRD 章节覆盖率（SenseCare 模式）
- 已覆盖：4.1、4.2
- 未覆盖：4.3（原因：...）
```

## 实施细则

### 页面与路由建议

- 至少包含：
  - 首页/概览页
  - 核心流程页（1~3个）
  - 结果/详情页
- 路由命名与文件命名保持一致，避免含糊缩写。

### 状态管理建议

- 按业务域拆分 Pinia：
  - `useUserStore`
  - `useProductStore`
  - `useFlowStore`
- Store 中区分：
  - 原始 Mock 数据
  - UI 派生状态
  - 用户交互动作

### Mock 数据建议

- 放置在 `src/mock/`。
- 使用可读 JSON 或 JS 模块导出。
- 使用“内存态 Mock 仓库”支持 CRUD：新增、编辑、删除后应即时反映到列表与详情。
- 每个核心流程至少覆盖：
  - 空状态
  - 正常状态
  - 异常提示状态

建议最小结构：
- `src/mock/<domain>.mock.js`：初始数据种子
- `src/mock/<domain>.repo.js`：CRUD 方法（`list/get/create/update/remove`）
- `src/stores/<domain>.store.js`：调用 repo 并维护 UI 状态

### Ant Design Vue 使用建议

- 优先使用标准组件组合（表单、表格、抽屉、弹窗、步骤条）。
- 交互反馈统一用 `message`/`notification`，避免混乱。
- 仅在 PRD 明确需要时新增复杂自定义样式。

## 质量门槛（完成前自检）

- [ ] 能成功 `npm install` 与 `npm run dev`
- [ ] 所有核心路由可访问
- [ ] 每条 PRD 需求都有 `Rxx` 映射（SenseCare 模式下编号与 `3. 需求总览` 表格一致）
- [ ] 映射表中“已实现/未实现”状态准确
- [ ] 无后端依赖即可完整演示核心流程
- [ ] 至少 1 个核心实体支持可演示 CRUD 全流程
- [ ] **PRD 中明确写出的数字常量（防抖/超时/字数上限/缓存清理时长等）已 1:1 落地到 `src/constants/`，未被擅自改成默认值**
- [ ] **PRD 中双引号包裹的静态文案、占位符、空态文案已 1:1 落地，未被擅自改写**
- [ ] **SenseCare PRD 模式下，每个 `4.x.2` Mermaid 中的命名状态在对应 store 中均有 `state` 值映射**

## 禁止事项

- 不要跳过“需求映射表”直接写代码
- 不要默认接入真实后端或数据库
- 不要在未说明的情况下切换技术栈
- 不要使用与 PRD 无关的过度工程化方案
